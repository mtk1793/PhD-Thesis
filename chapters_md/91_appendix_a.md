# Appendix A: Reproducibility and Software Environment

This appendix documents the software environment, the data acquisition and verification procedure, the provenance and seed policies, and the mapping from figures to generating scripts, so that every Stage-1 result in this thesis can be regenerated by a third party. The guiding principle is that reproducibility is a property of the whole chain, from the raw data download to the figure files, and not merely of the analysis code. The Stage-1 rebuild was therefore engineered with pinned dependencies, hashed data, fixed seeds, and scripted artefacts from the outset, and this appendix records those engineering decisions in the form needed to repeat them.

The software environment is Python 3.10 or later, and all Stage-1 experiments run on CPU only; no discrete GPU is required for any offline result in this thesis. The dependency set is deliberately small and pinned to verified versions: PYPOWER 5.1.21 for the Newton power flow [41], NumPy 2.1.3 for numerical arrays [120], pandas 2.2.3 for time-series handling [119], PyTorch 2.14.0 for the CNN-LSTM implementation [35], matplotlib 3.9.2 for figure generation, and supporting packages (scipy 1.14.1, scikit-learn 1.5.2, requests 2.32.3, pyarrow 25.0.1, pytest 9.0.2) as pinned in the repository requirements file. Reinstalling the environment is a single command, python -m pip install -r requirements.txt, and the CPU-only PyTorch wheel index documented in the repository avoids an unnecessary GPU dependency. Hardware requirements are modest: 8 GB of RAM is the practical minimum for the 118-bus runs, 64 GB is recommended for comfortable multi-system execution, and complete single-phase runs, including the full January 2019 six-controller benchmark, complete in minutes on a contemporary workstation.

The data foundation is the Open Power System Data time-series package, version 2020-10-06 [42], and its acquisition is scripted end to end. The command python scripts/phase0_data.py downloads the hourly and 15-minute single-index CSV files directly from the package URL, checks each file against a minimum-size guard, computes the SHA-256 digest, and writes the result to data/raw/provenance_manifest.json together with the download timestamp; the phase 1 command python scripts/phase1_data.py then applies the gap policy of Chapter 2 and produces the disaggregated profiles used by all later phases. Independent verification of the raw files is possible without the pipeline, for example with sha256sum time_series_60min_singleindex.csv on the hourly file, which should reproduce the digest recorded in the manifest: the hourly file is 130,339,665 bytes with SHA-256 beginning 6a7f2bc571314cbf, and the 15-minute file is 112,072,477 bytes with SHA-256 beginning 194f3ee7d110d043. A mismatch at either file indicates a corrupted or altered download and must be resolved before any experiment is run, since every downstream number inherits the hash of its input.

The provenance manifest serves as the single point of truth for data identity. It records the dataset name and version, the DOI, the primary source attribution to the ENTSO-E Transparency Platform, the verification timestamp, and, for each file, the URL, the byte count, the size check, and the full SHA-256 digest. The integrity report generated alongside it records the missing-data census before and after the gap policy of Chapter 2, so the completeness claims of Section 11.1 trace to a machine-readable artefact rather than to prose. Together the manifest and the integrity report allow a reviewer to confirm, without rerunning anything, that the data on disk at review time is the data used at submission time.

The seed policy fixes every source of randomness that the results depend on. The QIRL controller is constructed with a fixed seed of 42 in all phase scripts, which governs the candidate initialisation, the Born-rule sampling, and the tunneling replacements; the training scripts seed the framework's random generators before model initialisation and data shuffling; and the environment's internal random generator is instantiated from an explicit seed whenever stochasticity is enabled, with deterministic experiments passing no seed at all. Behaviour cloning is deterministic given the seed, and the phase scripts write their summaries to the results directory so that a rerun either reproduces the recorded metrics bit for bit or exposes the discrepancy. The model weights themselves, notably results/phase4/system1_cnnlstm.pt, are committed artefacts, which decouples reproduction of the benchmark results from retraining.

Reproducing the full Stage-1 pipeline is therefore a sequence of documented commands: install the pinned environment, run the phase 0 and phase 1 data scripts and verify the digests, then execute the phase scripts in numeric order (python scripts/phase2_grid.py through python scripts/phase6_arbiter.py), each of which writes its summary, its figures, and its logs into the results tree. The whole sequence completes on a workstation within an hour, and its outputs are the numbers, the tables, and the figures of Part A of Chapter 11.
